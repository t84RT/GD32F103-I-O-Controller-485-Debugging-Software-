## 1. 项目定位与系统组成

项目围绕一块具备 RS485 接口的 I/O 板卡，提供配套 Windows 上位机。目的不是让画面“看起来在通信”，而是让操作者知道：请求发给了谁、响应是否可信、当前数据显示是否新鲜、一次输出动作覆盖哪些通道，以及停止操作之后还可能保留什么状态。

系统的公开视图如下：


~~~text
Windows PC / IOCON 上位机
        ⇅ Modbus RTU 请求与响应
USB-RS485 转换器 / 已确认接线的 RS485 总线
        ⇅
配套 I/O 板卡：公开通信接口，内部实现不公开
        ⇅
经确认的输入信号、输出负载、模拟量信号
~~~

本工具适合台架联调、逐点核对、通信排错、教学演示和受控条件下的记录分析。不能直接将跑马灯用于已连接电机、阀、加热器或其他危险负载的设备。

## 2. 通道与电气边界

| 项目 | 物理通道 | 当前用途与限制 |
| --- | --- | --- |
| 数字输入 | X0～X15，共 16 路 | 只读状态显示 |
| 数字输出 | Y0～Y31，共 32 路 | Y17 为通信专用灯，其余 31 路供普通控制 |
| 普通可控输出 | Y0～Y16、Y18～Y31 | 手动翻转、全开、全关、跑马灯均使用这 31 路 |
| 模拟量 | A0～A5，共 6 路 | 显示 ADC 原始值，不自动换算电压、电流或工程单位 |
| 兼容保持寄存器 | 地址 0～18，共 19 项 | 保留兼容接口；业务名称与字段定义不在公开文档展示 |
| 只读诊断区 | 0x0100～0x010F，共 16 字 | 用于板卡识别、运行及通信统计 |

**不要把协议地址数量当作物理端子数量。** 线圈和离散输入兼容读取空间均为 0～63，但 Y32～Y63、X16～X63 为保留或扩展空间，并不代表当前有对应端子。

本文不提供未经确认的输入额定电压、输出驱动类型、负载电流、隔离耐压、防护等级、模拟量量程或标定参数。不能据此认定它支持某种 PNP/NPN 接法、继电器负载、0～10 V 或 4～20 mA。**A5 也不是 24 V 电源监测通道。** 接线与外部保护必须以实际硬件资料及测量确认结果为准。

## 3. 通信参数与首次连接

### 默认配套参数

| 参数 | 默认值 | 上位机可选范围 |
| --- | --- | --- |
| 站号 | 3 | 必须与目标设备一致 |
| 波特率 | 115200 | 9600、19200、38400、57600、115200、230400 |
| 数据位 | 8 | 7 / 8 |
| 校验 | 无 | 无 / 偶 / 奇 |
| 停止位 | 1 | 1 / 1.5 / 2 |
| 请求超时 | 300 ms | 100～5000 ms |
| 轮询间隔 | 100 ms | 50～5000 ms |

配套默认设置为 **115200、8-N-1、站号 3**。上位机提供某个选项，不代表板卡固件支持在线切换到该选项，也不代表所有组合均已实机验证。改变这里的串口参数只是改变主站连接设置，不会自动远程改写板卡配置。

### 推荐首次操作顺序

1. 不接危险执行负载，先确认供电、电气接口及 RS485 接线。
2. 安装转换器驱动，确认端口号；必要时点击串口刷新。
3. 设置与设备一致的站号和串口参数，打开串口。
4. 启动只读轮询，观察输入、输出、ADC 与诊断是否刷新。
5. 核对 RX、错误提示和日志，不以“串口打开成功”当作“设备响应正常”。
6. 确认普通输出的物理对应关系，再进行空载或受控负载的单点测试。
7. 需要批量演示时，再确认覆盖范围、Y17 保留规则和独立停止措施。
8. 操作结束按既定流程处置输出，不能仅退出软件就认为负载已断开。

连接建立后不会自动开启普通输出。读取已有输出状态不等于设置输出。

## 4. 上位机全部工作区

### 4.1 顶部连接与操作区

提供串口刷新、打开/关闭串口、站号与串口参数设置、超时与轮询间隔设置、开始/停止轮询、31 路全开、31 路全关、跑马灯开始/停止，以及“记录轮询帧（限量）”选项。

危险动作保持明确的文字和红色语义，不靠单一图标表达。最小客户区保持 1040×760，默认客户区 1280×920；缩放覆盖范围请参见验证章节，不承诺任意字体、任意多屏组合均已验收。

### 4.2 现场 I/O 概览

- 16 路输入：逐路显示 X0～X15 的读取值。
- 32 路输出：展示 Y0～Y31；Y17 用蓝色提示“485”，只读不可点击。
- 6 路模拟量：A0～A5 的原始值及条形提示，不是标定后的工程量。
- 状态提示：ONLINE、POLL、RX、TX、ALARM，以及协议识别、最近响应等信息。

ONLINE 反映有效响应的新鲜程度，不是板卡物理供电灯；软件 RX/TX 是软件事务提示，不等同于收发器电气引脚。ALARM 可能提示通信等待、数据过期或其他会话问题，不属于独立安全报警链。

显示旧值不代表旧值仍然有效。数据过期时，面板点击控制会禁用，避免用陈旧状态做翻转依据。

### 4.3 保持寄存器页

展示 19 项兼容保持寄存器，支持十进制和带 0x 前缀的十六进制值输入。通过功能码 06 进行单项写入，写前确认，写后读回。

公开文档不披露这些寄存器的业务字段，也不建议陌生设备试写。它们**不是通用看门狗配置区**，不能将某个地址凭经验解释为超时、掉线保护或安全设置。不了解业务定义时，仅做读取。当前没有独立的批量寄存器编辑器。

### 4.4 板卡只读诊断页

读取 FC04 / 0x0100～0x010F，展示接口签名、协议版本、站号、波特率、通道数、运行时间、通信计数和能力位。该区域与 ADC 区分开，不改变输出状态。

兼容旧设备时，诊断返回非法地址异常 02，会停止对不支持区域的探测；一次暂时超时不会永久判定为旧设备，后续可以重试识别。不支持诊断并不等于原有 I/O 接口不可用。

### 4.5 帧监视与日志页

支持输入**不含 CRC** 的原始请求，软件自动添加 CRC。可接受空格、逗号、分号分隔、连续十六进制或 0x 字节表示；拒绝杂字符、缺半个字节等输入。原始帧站号必须与当前选定站号相同。

功能 01～04 按读取处理；其他原始请求发送前弹出风险确认。原始请求并不是安全旁路：不要用它规避对未知寄存器、保留输出及负载条件的确认。

日志区区分 TX 与 RX(raw)。看到原始接收字节不表示响应通过验证；只有符合本次请求的有效响应，才计入有效 RX。支持清空、导出文本和限量记录轮询帧。导出包含当时状态、会话统计与当前可见日志，不是完整数据库或永久审计链。

### 4.6 长稳统计页

展示会话时长、TX、有效 RX、错误数、完整轮询次数、全成功/非全成功轮询、最近/最大响应延迟、最近错误与诊断识别状态。

一轮完整轮询包含 X、Y、ADC、兼容寄存器等多个事务，不是硬件原子快照。不同值的采集时刻可能不同。会话统计不代表永久运行记录，也不能仅凭高成功率证明带载安全或现场抗干扰合格。

### 4.7 说明与安全页

集中说明使用顺序、地址含义、Y17 保留、停止语义、输出风险及硬件验收建议。阅读该页不会自动完成现场风险评估，仍需结合实际负载、接线和安全回路落实措施。

## 5. Y17 通信指示灯：用途与外部行为

Y17 已从普通控制输出中分离，专用于通信活动提示。原来接在 Y17 上、需要固定状态控制的负载必须先调整，不能继续把它当作普通输出。

- 初始化为关闭。
- 本站、CRC 正确、功能受支持且格式合法的请求会触发活动。
- 格式合法但访问地址不合法的请求，也可以触发通信提示；因此“灯闪”不等于业务执行成功。
- 活动期间按约 **100 ms 亮、100 ms 灭** 的节奏闪烁。
- 连续有效请求延长活动窗口，不反复重启闪烁相位，避免高频轮询导致视觉常亮。
- 最后有效请求之后约 **500 ms** 熄灭。
- 错站号、广播、CRC 错误、未知功能、格式错误或接收溢出不触发或续期。

| 访问方式 | Y17 的处理 |
| --- | --- |
| FC01 读取线圈 | 可以读取灯的当前值 |
| FC05 单独写 Y17 | 返回异常 02，不允许作为普通输出写入 |
| FC0F 范围覆盖 Y17 | 忽略 Y17 对应位，其他普通输出位正常处理并正常回显 |
| 上位机全开、全关、跑马灯 | 主动跳过 Y17 |

特别注意：FC0F 的正常回显不证明 Y17 接受了写入。Y17 只是合格请求活动提示，不是总线电气健康、电源状态、每条业务成功或设备安全状态的证明。

## 6. 输出控制与完整跑马灯

### 单点翻转

点击普通 Y 通道时，先读取当前状态，再执行翻转，再读回确认，不靠本地按钮颜色“猜”设备状态。演示期间禁止手动翻转，以免两种意图同时争用普通输出。

### 全开与全关

操作范围为 Y0～Y16、Y18～Y31，共 31 路。全关会停止演示、清理待执行队列并优先处理普通输出关闭，但不能撤销已经发送或设备已经执行的动作。Y17 不在全关范围内，仍由通信活动决定。

“全关”本身依赖上位机、转换器、总线、板卡和供电链路，通信故障时可能无法到达，因此不是硬件急停。

### 跑马灯

原先仅覆盖低位通道的演示已扩展为 **31 路逻辑环**，覆盖 Y8 之后的高位输出及 Y31，并跳过 Y17。每步点亮逻辑环上相邻的三路，按约 150 ms 的步进间隔推进；实际周期还要加通信、轮询和系统调度耗时，不是 PWM 或精密时序控制。

每步对 0～16、18～31 两个范围分别使用 FC0F，再用 FC01 读回。两段写入**不是原子操作**：后一段失败时，前一段可能已经执行，不能宣称同时切换、事务回滚或所有输出必然恢复原值。

任一写入或读回失败会停止演示，不自动重试写入。**停止演示、停止轮询、关闭连接均不会自动清除输出**，停止瞬间也可能有在途动作已发生。请用明确的收尾流程和独立硬件措施管理负载。

## 7. Modbus RTU 外部接口

### 7.1 功能码与界面入口

| 功能码（十六进制） | 能力 | 当前上位机入口 |
| --- | --- | --- |
| 01 | 读线圈 | 输出显示、读回及原始请求 |
| 02 | 读离散输入 | 输入显示及原始请求 |
| 03 | 读保持寄存器 | 兼容寄存器页及原始请求 |
| 04 | 读输入寄存器 | ADC、只读诊断及原始请求 |
| 05 | 写单线圈 | 普通输出翻转及原始请求 |
| 06 | 写单保持寄存器 | 单项写入并读回 |
| 0F | 写多线圈 | 全开、全关、跑马灯及原始请求 |
| 10 | 写多保持寄存器 | 协议层支持；可人工构造原始请求，无独立批量编辑页 |

支持八个功能码，不意味着界面有八个独立编辑页面。当前不是通用任意寄存器工程平台，也没有交互式模拟从站或 Modbus TCP。

### 7.2 零基地址表

| 数据 | 功能码 | 起始地址 | 数量 | 说明 |
| --- | --- | --- | --- | --- |
| 普通/专用输出状态 | 01 | 0 | 32 | 包括只读通信灯 Y17 |
| 兼容线圈空间 | 01 | 0 | 最大到地址 63 | 32～63 为保留/扩展，不是物理输出 |
| 数字输入 | 02 | 0 | 16 | X0～X15 |
| 兼容离散输入空间 | 02 | 0 | 最大到地址 63 | 16～63 为保留/扩展 |
| ADC 原始值 | 04 | 0 | 6 | A0～A5 |
| 兼容保持寄存器 | 03 / 06 / 10 | 0 | 19 | 业务定义脱敏，未确认不得写 |
| 只读诊断 | 04 | 0x0100 | 16 | 与 ADC 分区，不能跨中间空洞一次读取 |

本表仅披露通用 I/O、兼容保持寄存器的地址范围及只读诊断；历史兼容扩展不属于本文公开范围，不应据此枚举或试写其他地址。

本文地址均指帧中的**零基协议地址**。第三方软件若使用 40001、30001 等显示约定，应先确认其换算方式，不能直接将显示号填进原始帧。

### 7.3 只读请求示例

以下均为站号 3 的**无 CRC 输入内容**，适合输入本工具原始请求框；不是可直接发送到串口的完整 RTU 帧。其他工具若不自动补 CRC，需要自行按其说明处理。

| 无 CRC 请求 | 用途 |
| --- | --- |
| 03 02 00 00 00 10 | 读取 16 路数字输入 |
| 03 01 00 00 00 20 | 读取 32 路输出，含 Y17 |
| 03 04 00 00 00 06 | 读取 6 路 ADC 原始值 |
| 03 04 01 00 00 10 | 读取 16 字只读诊断 |

本文不提供一键驱动全部输出的原始写帧。真实写入前必须确认通道、覆盖范围、负载状态及操作授权。

### 7.4 异常与无响应边界

- 异常 01：不支持的功能。
- 异常 02：非法地址或只读限制等。
- 异常 03：格式、数量、长度或 FC05 写入值等不合法。
- 错误 CRC、其他站号和广播等不产生本次有效应答。
- 当前配套接口对站号 0 的广播沿用忽略策略，不提供广播控制演示；原始请求也要求站号与当前选择一致。

不能把异常响应当普通数据；同样不能把所有无响应都归咎于板卡，需要分开检查站号、参数、接线、超时和转换器。

## 8. 只读诊断寄存器

使用 FC04 读取 0x0100～0x010F，全部为只读。当前协议版本字段为 **0x0102**，界面按 **1.02** 显示；这不是上位机 v1.3.0 的文件版本。

| 地址 | 字段 | 解释 |
| --- | --- | --- |
| 0x0100 | 接口签名 | 0x494F，用于识别配套 I/O 接口 |
| 0x0101 | 协议版本 | 当前 0x0102 |
| 0x0102 | 站号 | 设备当前站号 |
| 0x0103 | 波特率低字 | 与下一字组合 |
| 0x0104 | 波特率高字 | 高 16 位 |
| 0x0105 | 数字输入数量 | 16 |
| 0x0106 | 数字输出数量 | 32，含 Y17 |
| 0x0107 | ADC 数量 | 6 |
| 0x0108 | 运行秒数低字 | 与下一字组合 |
| 0x0109 | 运行秒数高字 | 高 16 位 |
| 0x010A | 格式有效请求数低字 | 不等于业务全部成功 |
| 0x010B | 格式有效请求数高字 | 高 16 位 |
| 0x010C | 本站地址 CRC 错误计数 | 饱和计数 |
| 0x010D | 接收溢出计数 | 饱和计数 |
| 0x010E | 格式错误计数 | 饱和计数 |
| 0x010F | 能力位 | bit0 = 支持 Y17 通信灯 |

跨两字的无符号数按“低字 + 高字 × 65536”组合。计数在设备重启后清零，不是掉电保存的历史记录；饱和计数达到上限后不能继续反映新增错误的数量。格式有效但地址异常的请求也可能计入格式有效请求数，不能直接计算为业务成功次数。

## 9. 上位机可靠性设计

以下只介绍公开侧上位机设计，不涉及板卡内部实现：

1. **单一串口所有者**：后台工作线程负责串口，轮询、手动动作和原始请求串行排队，避免不同入口抢收响应。
2. **有界命令队列**：容量 64，避免 UI 高频操作无限堆积。排队不等于设备已经执行。
3. **快照式界面刷新**：界面读取数据副本，不直接操作后台共享串口数据。
4. **会话生命周期同步**：关闭时等待旧工作线程退出，再允许建立新会话，避免旧连接干扰新连接。
5. **整帧总超时**：零碎接收字节不会无限延长一次请求。
6. **事务间隔控制**：按主站事务节奏限制请求，不把轮询间隔当成无条件满速发送。
7. **严格核验响应**：站号、CRC、功能码、长度、字节数及写回显等与当前请求匹配后才计为有效。
8. **失败不自动重写**：自动演示失败即停止；不通过无条件重试掩盖输出执行状态的不确定性。

这些措施降低已知的软件风险，但不能代替硬件保护、现场验证或功能安全设计。读回输出状态也不能证明外部负载实际动作，需要独立反馈时必须另行设计。

## 12. 常见问题

| 现象 | 优先检查 |
| --- | --- |
| 串口打不开 | 端口是否存在、驱动是否正确、是否被其他软件占用、是否仍在旧会话关闭过程中 |
| 串口能开但没有数据 | 站号、115200/8-N-1 等参数、RS485 接线与电气条件、超时和转换器状态 |
| Y17 不闪 | 是否确有本站格式合法请求；错误 CRC、广播或未知功能不触发；旧接口也可能不支持 |
| 高频轮询时 Y17 是否应该常亮 | 不应该因每次请求重置相位而一直亮；活动窗口与闪烁节奏是不同概念 |
| 全关后 Y17 仍闪 | 正常，Y17 是通信专用，不属于 31 路普通全关范围 |
| Y8 之后没有参与演示 | 确认运行的是当前发布版本、不是旧窗口；确认读回与地址对应，再查真实接线 |
| 停止演示后还有输出亮 | 停止不自动清输出；按受控流程处理，不能把软件停止当急停 |
| 两组输出没有同时切换 | 两段 FC0F 是非原子动作，不提供同步输出承诺 |
| ADC 数字不像电压 | 当前显示原始值，无量程、标定和工程单位转换；A5 也不是 24 V 电源监测 |
| 诊断页显示兼容模式 | 可能为旧接口或暂时尚未识别；结合异常码和后续探测判断，不影响已支持的基本读取 |
| 日志中有 RX 但有效 RX 不增加 | 收到了字节，不代表响应通过站号、CRC、功能或长度校验 |
| 通信成功率很高但现场仍不稳 | 继续检查电源、负载、接线、地电位、干扰和物理反馈，软件统计不能覆盖全部风险 |
